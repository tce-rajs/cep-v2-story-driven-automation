## What this project is

Playwright suite (`tests/`) driving the **real Tata ClassEdge School Electron desktop client** (not a browser)
against `ce-qa-school.devstudi.com` (QA server, Goyal Brothers School). Single shared QA account/session,
`workers: 1` — only one Electron/Playwright process may run against the client at a time. Story files live in
`CEPV2_Stories/*.md`; `scripts/build-workbook.js` rebuilds `CEPV2_Stories/CEPV2_TestCases.xlsx` from them (655 test
cases as of this session).

## What was done this session

1. **Real touch/stylus/pen input testing** — added `pages/touch-input.js` (a CDP-based `TouchInput` class:
   tap, longPress, fingerStroke, twoFingerPan, pinch, mouseStroke, penStroke, penStrokeWithPalm) so tests drive the
   whiteboard the way a teacher actually would on a classroom touch panel, not just with `page.mouse`.
   - **Critical lesson learned**: dispatching a whole stroke's touch/mouse-move events as one `Promise.all` burst
     makes Chrome merge them and the app draws a jagged, simplified line, dropping most strokes (confirmed: 223 of
     1,480 landed in one run). Fixed by sending one move at a time with a small delay. See the comment in
     `pages/touch-input.js`.
2. **Realistic handwriting generator** — `pages/lib/handwriting.js` turns a word count into human-like joined pen
   strokes laid out across a whiteboard area, used by the long-session tests below.
3. **Long-session / never-cleared whiteboard tests** (`tests/06-whiteboard/wb-08-*`, `wb-09-integrity.spec.js`,
   `wb-10-touch-stylus.spec.js`, `wb-11-teacher-day.spec.js`) — explicitly test that content **persists across
   sign-out/sign-in and app close/reopen without ever clearing the board**, per the owner's real-world scenario
   ("teacher writes, signs out, writes again on the same topic by panning, writes again — nothing should be lost").
   These use a dedicated `longSession` key in `config/moduleClassMap.js` with a comment warning not to add
   `cleanBoard` to any test using it.
   - `wb-08-04-close-app.spec.js`, `wb-11-teacher-day.spec.js`, and `tests/03-login/log-01-14-client-reopen.spec.js`
     are **standalone "raw client launch" files** (they call `launchWithRetry()` directly instead of the normal
     fixture) because they need to actually close and reopen the Electron app mid-test. Playwright schedules these
     at the very end of a run regardless of which folder they're in — don't assume the suite is stuck if the log
     goes quiet for 10-15 minutes right at the end; these tests are just slow (WB-11-01 alone took 15.5 minutes).
4. **Multi-click tests** for every asset type (`tests/11-players/plr-13-multi-click.spec.js`,
   `tests/08-playlist/pl-10-multi-click.spec.js`, `tests/07-class-navigation/nav-07-fast-switch.spec.js`).
5. **Annotation-on-every-asset-type tests** (`tests/11-players/plr-14-annotate-every-asset.spec.js`, 39 tests) —
   zoom+write+pan+write, every tool, persistence after close/reopen, and the specific real-world case of annotating
   a playing video.
6. **Upload test-data kit** — `scripts/make-test-data.js` (+ `scripts/lib/mini-zip.js`,
   `scripts/lib/office-docs.js`) builds `test-data/` (gitignored, rebuild locally with
   `node scripts/make-test-data.js`): 29 real-teacher-style files + 21 broken/wrong/oversized/unsupported ones. Run

7. **Evidence capture pipeline** — `RECORD_VIDEO_DIR` env var on `electron.launch()` records video (this works for
